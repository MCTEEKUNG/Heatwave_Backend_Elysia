B · สองโลกของโมเดล

Production vs Training-Dashboard

คำถามใหญ่: “โมเดลบน Production คนละตัวกับที่เทรนใน dashboard ไหม?” — ไม่ใช่วิกฤต ทั้งคู่อ่าน dataset ไฟล์เดียวกัน เพียงแต่ artifact ใน dashboard เป็นของเก่าค้าง

🟢 Production (ที่เว็บใช้)

models/heatwave_model.pkl

  • 77 จังหวัด · ERA5 1991–2025
  • เทรน 5 มิ.ย. ด้วย train_production.py
  • ขึ้นเว็บผ่าน Supabase ✅

🧪 Training-Dashboard (sandbox)

models/dashboard/*.pkl

  • artifact เก่า: 20 จังหวัด (30 พ.ค.)
  • ไม่ auto-deploy โดยตั้งใจ (กันเผลอทับ)
  • อ่าน dataset.parquet ไฟล์เดียวกับ production
กุญแจ: ทั้งสองอ่าน data/processed/dataset.parquet ซึ่งตอนนี้ = 77 จังหวัด, 984,368 แถว. โมเดล 20 จว. ใน dashboard เป็นของที่เทรน “ก่อน” ไฟล์ถูก rebuild ไม่ใช่คนละ dataset
C · ไทม์ไลน์

ทำไม dashboard ได้ 20 จว. แต่ production ได้ 77

  • 30 พ.ค. — เทรนใน dashboard ตอน dataset.parquet ยังเป็น 20 จังหวัด → ได้ models/dashboard/*.pkl 20 จว.
  • 5 มิ.ย. 15:48 — rebuild dataset.parquet → กลายเป็น 77 จังหวัด
  • 5 มิ.ย. 15:53 — เทรน production จากไฟล์ใหม่ → heatwave_model.pkl 77 จว.
  • 6 มิ.ย. — Supabase regenerate → เว็บแสดง 77 จว. (ตรวจแล้ว prod == local)
D · บั๊ก Map “เขียวล้วน”

“เขียว” = ปลอดภัย หรือ โหลดไม่ขึ้น?

เดิม grid เป็นสีเขียวทั้งใน ตอนโหลดพลาด และ ตอนเสี่ยงต่ำจริง — แยกไม่ออก (Render free tier cold start ทำให้ fetch หลุดบ่อย). แก้แล้วให้ “ไม่มีข้อมูล” = สีเทา + ปุ่มลองใหม่

สิ่งที่แก้ (fan-out 3 agents)

  • Map: state loading/error/empty/ready, เทาแทนเขียว, ปุ่ม Retry, ป้าย “As of …”
  • Alerts: roll-up + province ขึ้น loading/error/retry แทน “all-clear” ลวงตา
  • Backend: ลบ v1 endpoints ที่ตายแล้ว + ไฟล์ orphan

ยืนยันจริง: ปิด backend → เทา+Retry → เปิด+กด Retry → กลับมาหลากสี · lint 0 errors

G · เทียบ metric
