1 ภาพรวมโปรเจกต์

โปรเจกต์นี้คือระบบ พยากรณ์คลื่นความร้อน (heatwave) รายจังหวัดของไทย ทำนายล่วงหน้า 1–7 วัน ต่อจังหวัด เป็นปัญหา rare-event (วันคลื่นความร้อนมีเพียง ~4%). มี 4 codebase อยู่ในรากเดียวกัน — ต้องรู้ก่อนว่ากำลังแก้ codebase ไหน (จุดสับสน: โฟลเดอร์ src/ ปนกันระหว่าง Python ML กับ TypeScript backend).

5.1 กฎข้อ #1 — ฟีเจอร์ antecedent-only (กัน leakage)

หัวใจทั้งโปรเจกต์: ทุกฟีเจอร์สร้างด้วย .shift(1).rolling(...) ค่าของวัน t เองจึงไม่เคยเข้าไปเป็นฟีเจอร์ของตัวเอง. target คือ heatwave.shift(-k) (heatwave อีก k วันข้างหน้า).

src/features.pyบรรทัด 31–50
def _antecedent_features(d: pd.DataFrame) -> pd.DataFrame:
    """Rolling mean/max + climatology anomaly of past-only values.
    All rolling stats operate on .shift(1) so the current day's value is
    never part of its own feature (no same-day leakage)."""
    feats = {}
    for col in _VALUE_COLS:
        if col not in d.columns:
            continue
        past = d[col].shift(1)  # values strictly before day t
        for w in _ROLL_WINDOWS:
            roll = past.rolling(window=w, min_periods=w)
            feats[f"{col}_mean_{w}d"] = roll.mean()
            feats[f"{col}_max_{w}d"]  = roll.max()
        # anomaly of yesterday's value vs the static per-doy p95 climatology
        if "p95" in d.columns:
            feats[f"{col}_anom_lag1"] = past - d["p95"]
    return pd.DataFrame(feats, index=d.index)

5.2 Label — percentile + persistence

วันคลื่นความร้อน = ค่า ≥ p95 ของ day-of-year ตำแหน่งนั้น และ อยู่ในช่วงเกินติดต่อกัน ≥ 2 วัน.

src/labels.pyบรรทัด 10–23
def label_heatwave(df, thresholds, value_col="swbgt_max", min_run=2):
    d = df.copy()
    d["doy"] = d["time"].dt.dayofyear
    d = d.merge(thresholds[["doy", "p95"]], on="doy", how="left")
    d["is_hot"] = (d[value_col] >= d["p95"]).astype(int)
    # group consecutive equal is_hot values into runs, measure run length
    grp = (d["is_hot"] != d["is_hot"].shift()).cumsum()
    run_len = d.groupby(grp)["is_hot"].transform("size")
    d["heatwave"] = ((d["is_hot"] == 1) & (run_len >= min_run)).astype(int)
    return d.drop(columns=["doy"])

def build_forecast_rows(daily, province_id, issue_date):
    """Open-Meteo `daily` dict -> rows with lead_k and forecast heat index."""
    issue = pd.Timestamp(issue_date).normalize()
    rows = []
    for t, tx, h in zip(times, tmax, rh):
        target = pd.Timestamp(t).normalize()
        lead = int((target - issue).days)
        if lead < 0 or tx is None or h is None:
            continue
        rows.append({
            "province_id": int(province_id),
            "issue_date":  issue.date().isoformat(),
            "target_date": target.date().isoformat(),
            "lead_k": lead,
            "fc_tmax": float(tx), "fc_rh": float(h),
            "fc_heat_index": float(heat_index_c(tx, h)),  # ตรงกับ label
        })
    return rows

def plan_schedule(n_provinces, batch_size, sleep_s) -> dict:
    """Pure arithmetic, no side effects. Sleep only BETWEEN batches."""
    if n_provinces <= 0:
        return {"n_batches": 0, "est_seconds": 0}
    n_batches = math.ceil(n_provinces / batch_size)
    est_seconds = (n_batches - 1) * sleep_s
    return {"n_batches": n_batches, "est_seconds": est_seconds}

Antecedent-only เท่านั้น. ทุก value feature ผ่าน .shift(1).rolling(...). ค่าของวันเป้าหมายเป็นฟีเจอร์ = leakage.
✓
Temporal split เท่านั้น ห้าม random. เทรนปีก่อน → val/test ปีหลัง. random split บนข้อมูลอากาศ autocorrelated = leakage (ได้คะแนนปลอม ~0.99).
⛔
ERA5 / Historical-Forecast = analysis (ความจริง) ไม่ใช่ forecast. ใช้ของวันเป้าหมายเป็นฟีเจอร์ = leakage. API คืนค่า corr ≈ 1.0 กับ actual — อย่าเทรนกับมัน.
📊
Normalize PR-AUC ด้วย prevalence. สำหรับ rare-event no-skill floor = base rate. เทียบข้ามปีต้องหารด้วย base rate ก่อน.
📁
config.yaml ไม่ตรงกับโค้ดจริง: มันบรรยายดีไซน์ ERA5/MODIS-NDVI ที่ ยังไม่ได้ wire เข้า training. ให้เชื่อ docs/DATA.md + โค้ดจริง ไม่ใช่ config.yaml.

7 เช็กลิสต์ลำดับลงมือ

ลำดับที่ขยับระบบได้จริง — Track A เพื่อ "ขึ้น live", Track B ขนานไปเพื่อ "เก่งขึ้น".

🚀 Track A (เรียงตาม gate)

  • A0 USER แก้รหัส DATABASE_URL → ตรวจ OK forecasts rows=
  • A1 USER เทรน lgbm + Promote
  • A2 ME รัน run_daily_forecast.py → Supabase
  • A3 ตัดสิน Option A/B → deploy backend → /api/forecast/map ไม่ 404
  • A4 ตรวจ frontend แสดงสีจังหวัด
  • A5 ตัดสิน artifact story → ตั้ง cron อัตโนมัติ

📈 Track B (ขนาน)

  • B1 ตั้ง Task Scheduler รัน collect_forecast.py รายวัน 08:00
  • B2 ดึง GEFS spfh_2m → forecast heat-index → train_p0.py
  • B3 USER เลือก: forward-collect / ECMWF / จัดหาเอง
  • เมตริกเป้าหมาย: ROC 0.6 → ไปทาง 0.66+ ที่ short lead (ตาม noise model)
🎯
นิยาม "พอแล้ว": ไม่ใช่ตัวเลขลอย ๆ — คือ "ชนะ baseline ที่จะ deploy แทน (climatology F2 0.47, persistence 0.42) ที่ operating point ซึ่ง stakeholder ยอมรับ trade-off ระหว่าง false alarm กับ missed heatwave". ตัดสินกับคนที่ใช้ alert จริง ไม่ใช่กับตัวเลข.
