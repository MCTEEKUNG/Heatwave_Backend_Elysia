5 Overfit / "หลอน" หรือไม่ — วัดจริง

หมายเหตุศัพท์: "hallucination" เป็นของโมเดลภาษา (LLM). โมเดลนี้เป็น LightGBM classifier — ไม่ "หลอน" แบบสร้างข้อมูลเท็จ อาการที่เทียบเคียงคือ overfit (จำ noise ในชุดเทรนจนทำนายของใหม่พลาด) วัดได้จากช่องว่าง train↔test.

SplitROC-AUCPR-AUCF2base rate
TRAIN (≤2023)0.84960.20870.32550.038
VAL (2024)0.70350.44570.63700.243
TEST (2025)0.75350.33330.51130.137
🩺
คำตัดสิน: overfit เล็กน้อย–ปานกลาง ไม่ "หลอน". ช่องว่าง ROC train→test = +0.096. ถ้า overfit หนัก train ROC จะ ~0.98–0.99 แล้ว test ดิ่งเหลือ ~0.6 — แต่นี่ train แค่ 0.85 = จำไม่มาก. กลไกกัน overfit ที่มีอยู่: temporal split (กัน leakage), calibration + threshold จูนบน val (ไม่ใช่ test), scale_pos_weight คุม imbalance, Brier test ต่ำ. รองรับด้วย rolling-origin CV เดิม (ROC 0.734 ± 0.021, ความแปรปรวนต่ำ = generalize ได้จริง).
⚠️
ประเด็นที่ใหญ่กว่า overfit คือ base-rate shift: base rate ต่างกันมากระหว่างปี (train 3.8% → val 24.3% → test 13.7%) จากภาวะโลกร้อน + วิธีตั้ง threshold p95. นี่คือเหตุผลที่ F2 แกว่งข้ามปี — เป็น distribution shift ไม่ใช่การจำ (งานแก้: fixed-baseline p95 / per-region).

7 Operating point & ข้อเสนอ UX

7.1 Per-region threshold — ทดสอบแล้ว ไม่ใช่ win

ลองจูน threshold แยกรายภูมิภาคบน val 2024 แล้ววัดบน test 2025 — F2 รวมเปลี่ยน −0.008 (แย่ลงนิดเดียว). ไม่ generalize เพราะ base rate val ต่างจาก test. สรุป: ยังไม่ควร productionize — ใช้ threshold เดียว (0.1334) ต่อไป.

7.2 Two-tier operating point — แนะนำสำหรับ UX

แทนที่จะมีระดับเดียว เสนอ 2 ระดับ (เลือกจุดจาก val, วัดบน test 2025) ให้ผู้ใช้เข้าใจง่ายและสอดคล้องต้นทุนจริงของ "เตือนผิด" vs "พลาด":

8 เจาะลึก: บั๊ก CORS ที่ทำให้แผนที่ไม่ขึ้น

อาการ: เว็บจริงเปิดแผนที่แล้วว่างเปล่า. console ขึ้น No 'Access-Control-Allow-Origin' header is present แต่ curl เรียก API ได้ 200 ปกติ (curl ไม่บังคับ CORS).

Root cause (ยืนยันด้วย bisect)

route ที่ return ผลลัพธ์ของ library postgres (Result ซึ่งเป็น subclass ของ Array ไม่ใช่ plain) ตรงๆ ทำให้ @elysiajs/cors ไม่แนบ ACAO บน response จริง (OPTIONS preflight ยังผ่าน → บั๊กเนียนเหมือน config ผิด).

Routeชนิดที่ returnACAO บน GET?
/api/health, /plain object (sync)มี
/api/thresholds/:idobject ห่อ ({...})มี
/api/forecast/map, /api/provinces, /api/forecast/province/:idraw Resultไม่มี

Fix

// ก่อน — return Result ตรงๆ (CORS header หาย)
return sql`SELECT ... FROM heatwave.forecasts ...`;

// หลัง — spread เป็น plain array (CORS header กลับมา)
const rows = await sql`SELECT ... FROM heatwave.forecasts ...`;
return [...rows];
✓
ยืนยันบน production: PR #6 → master 88c5ea3 → Render deploy live. Playwright หน้า /map: 0 console error (เดิม 12), /api/forecast/map + /api/provinces = 200, แผนที่ขึ้นสี + "As of Jun 5, 03:54 PM" (= ข้อมูล run จริงเวลา 08:54 UTC).
