03โมเดลเก่งแค่ไหน — อ่านตัวเลขให้เป็น

โมเดลที่ใช้งานจริงตอนนี้คือ lgbm-v1 (เทรน 5 มิ.ย. 2026, 77 จังหวัด, 34 ฟีเจอร์) ทดสอบกับปี 2025 ที่โมเดลไม่เคยเห็นมาก่อน:

📊 ตัวเลขหลัก (ทดสอบปี 2025)

ROC-AUC — แยก "วันอันตราย" ออกจาก "วันปกติ" ได้ดีแค่ไหน0.754
F2 score — คะแนนรวมที่ให้น้ำหนัก "ห้ามพลาดเหตุการณ์จริง" เป็น 2 เท่า0.511
PR-AUC — ความแม่นเมื่อเหตุการณ์หายาก0.333
🧠 เปรียบเทียบง่าย ๆ: โมเดลเหมือนยามเฝ้าหมู่บ้านที่ขยันมาก — จับขโมยได้เกือบทุกครั้งที่มาจริง (recall สูง) แต่ก็เป่านกหวีดผิดบ่อย (precision ต่ำ ~0.23) ทีมจึงออกแบบระบบเตือน 2 ระดับ: "เฝ้าระวัง" สำหรับสัญญาณอ่อน และ "เตือนภัย" สำหรับสัญญาณแรง เพื่อไม่ให้คนเลิกเชื่อการเตือน

🏆 ชนะ baseline ไหม? ชนะ — นี่คือเกณฑ์ที่ถูกต้อง

คะแนนเดี่ยว ๆ ไม่มีความหมาย ต้องเทียบกับ "วิธีโง่ที่สุดที่ใช้ได้":

โมเดลของเรา (LightGBM)F2 ≈ 0.51–0.56
Climatology — "เดือนนี้ปีก่อน ๆ ร้อนไหม"F2 ≈ 0.47
Persistence — "พรุ่งนี้เหมือนวันนี้"F2 ≈ 0.42

🔭 การค้นพบสำคัญที่สุดของโปรเจกต์: "เพดาน" อยู่ที่ข้อมูล ไม่ใช่โมเดล

ลองโมเดล 7 ตระกูล (RF, XGBoost, CatBoost, LightGBM, MLP, ensemble…) ทุกตัวได้คะแนนเท่ากันหมด → แปลว่าอัลกอริทึมไม่ใช่คอขวด ทีมจึงทำ "oracle experiment": แอบใส่อากาศจริงของวันเป้าหมายเข้าไป (ทำไม่ได้จริง แต่ใช้วัดเพดาน)

04จุดแข็ง — สิ่งที่โปรเจกต์นี้ทำได้ดีจริง

ในมุมผู้รีวิว นี่ไม่ใช่โปรเจกต์ ML ทั่วไป — วินัยทางวิทยาศาสตร์อยู่ระดับงานวิจัย:

🔒

ออกแบบกัน Data Leakage ตั้งแต่ราก

ทุกฟีเจอร์ใช้ .shift(1) — ค่าของ "วันนี้" ไม่มีทางหลุดเข้าไปทำนายตัวเอง มีลิสต์ LEAKY_COLS ห้ามคอลัมน์ต้องห้าม และแบ่งข้อมูลตามเวลาเสมอ (เทรนปีเก่า ทดสอบปีใหม่) เพราะการสุ่มแบ่งข้อมูลอากาศรายวันจะได้คะแนนปลอม ~0.99

🔬

ซื่อสัตย์กับผลการทดลอง — รวมถึงผลที่ "ไม่สวย"

ตอนพบว่า API คืนค่า "พยากรณ์ย้อนหลัง" ที่จริง ๆ คือเฉลย (corr = 1.0000) ทีมทิ้งผลคะแนนสวยหรู F2 0.90 ทันที และบันทึกไว้เป็นบทเรียน เช่นเดียวกับ dataset ERA5 ใหม่ที่คะแนนต่ำลง — ก็รายงานตรง ๆ พร้อมวินิจฉัยสาเหตุ

🎲

ทดสอบนัยสำคัญทางสถิติ ไม่เชื่อตัวเลขลอย ๆ

ผลของ soil moisture (+0.008 ROC) เล็กจนใกล้ noise — ทีม bootstrap 1,000 รอบเพื่อพิสูจน์ว่า ผลจริงหรือบังเอิญ (CI ไม่ครอบ 0 = จริงแต่เล็ก) นี่คือมาตรฐานเดียวกับ paper วิชาการ

🔁

ทำซ้ำได้ทั้งหมด (Reproducible)

data/ ไม่เก็บใน git — สิ่งที่เป็น "ความจริง" คือสคริปต์สร้างข้อมูล ใครก็รันสร้าง dataset เดิมขึ้นมาใหม่ได้ มีเทสต์ 161 ตัวคุมทุกชิ้นส่วน

🚀

ครบวงจรถึงผู้ใช้จริง

ไม่ได้จบแค่ notebook — มี backend รันพยากรณ์รายวันอัตโนมัติ, แผนที่ในแอป, LINE bot และระบบ promote โมเดลที่มี guard + backup + rollback กันพังเวลาอัปเดต

05จุดที่ควรแก้ — เรียงตามความเร่งด่วน

ตรวจเจอจากการรันจริงวันนี้ ไม่ใช่จากเอกสาร:

P1

ตัวเก็บข้อมูลพยากรณ์รายวัน "ขาดวัน" — กระทบข้อมูลที่สำคัญที่สุดของอนาคตโปรเจกต์

Scheduled task HeatwaveForecastCollect ตั้งเป็น "Interactive only" — รันเฉพาะตอนล็อกอินเครื่องเท่านั้น ผลคือ 11 วันที่ผ่านมาเก็บได้แค่ 9 วัน (หายไป 2 วัน) ข้อมูลชุดนี้คือวัตถุดิบของแผน P0 ที่ต้องเก็บต่อเนื่องข้ามฤดูร้อน — ทุกวันที่หายคือรูในชุดข้อมูลที่ย้อนเก็บไม่ได้ตลอดกาล

เปลี่ยน task ให้รันแบบ "ไม่ต้องล็อกอิน" (schtasks /RU SYSTEM หรือ "Run whether user is logged on or not") หรือย้ายไปรันบน cloud cron (มี Render cron อยู่แล้ว) จะเสถียรกว่าแลปท็อปมาก

P2

เส้นทาง API เก่ายังเสิร์ฟโมเดลรุ่นเก่า

หน้า Map/Alerts ใช้โมเดลใหม่ (77 จังหวัด lgbm-v1) แล้ว แต่ route เก่า /forecast/latest ยังตอบด้วยโมเดล v1 (balanced_rf) ที่ล้าสมัย — ถ้ามีใครเรียกใช้จะได้คำตอบคนละเวอร์ชันกับแผนที่

ลบหรือ redirect route เก่าให้ชี้ไปข้อมูลชุดเดียวกับหน้า Map

P2

PR ค้าง 2 อันตั้งแต่เดือนพฤษภาคม — เนื้อหาล้าสมัยแล้ว

PR #1 (EDA/WBGT) เปิดก่อนการ rebuild dataset ใหญ่วันที่ 5 มิ.ย. และ PR #2 (AsyncStorage) ค้างมา 2 สัปดาห์ PR ที่ค้างนานจะ conflict สะสมและกลายเป็นขยะทางจิตใจ

ตัดสินใจอย่างใดอย่างหนึ่ง: rebase แล้ว merge หรือปิดทิ้งพร้อมโน้ตว่าเนื้อหาถูกแทนที่ด้วยอะไร

P3

Branch ปัจจุบันยาวเกินไป (25+ commits ยังไม่เข้า master)

feat/clean-era5-ndvi-dataset กลายเป็น branch หลักโดยพฤตินัย — มีทั้งงาน ML, UX, ops ปนกัน ถ้าเครื่องพังหรือ branch เสีย งานทั้งหมดเสี่ยง และชื่อ branch ไม่ตรงเนื้อหาแล้ว

merge เข้า master เป็นช่วง ๆ (งานทดสอบผ่านครบแล้ว ไม่มีเหตุผลต้องรอ)

P3

เศษไฟล์และความสับสนเล็กน้อย

ไฟล์ untracked ค้าง (bun_test_out.txt, docs/PROJECT-EXPLAINER.html), config.yaml อธิบายระบบที่ไม่ได้ใช้จริง (มีหมายเหตุใน docs แล้วแต่ยังหลอกคนใหม่ได้), และ src/ ปน Python กับ TypeScript ในโฟลเดอร์เดียว

ลบไฟล์ขยะ / commit ไฟล์เอกสาร, ใส่หมายเหตุหัวไฟล์ config.yaml ว่า "ไม่ได้ wired" — ส่วน src/ ปนภาษา รับรู้ไว้พอ (ย้ายตอนนี้ได้ไม่คุ้มเสี่ยง)
